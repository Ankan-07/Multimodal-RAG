# summarizer.py

This module handles the "multimodal" part of the system. The core insight driving its design is that a pure text embedding of a chunk containing a diagram or a data table is essentially lossy — the embedding won't capture what the image shows or what the numbers in the table mean. So for any chunk that contains images or tables, we use a vision-language model to generate a rich, searchable description before embedding.

`create_ai_enhanced_summary` constructs a multimodal message to the LLM. The text content and table HTML go into the text portion of the prompt, and the base64 images are attached as image URL blocks — this is the standard OpenAI vision API format, which OpenRouter passes through directly. The prompt is designed to maximize retrieval effectiveness rather than readability: we ask the model to enumerate facts, topics, potential questions, and alternative search terms. A chunk describing a transformer architecture diagram, for example, will get embedded with rich vocabulary like "encoder", "decoder", "multi-head attention", "residual connections" — terms a user might search for even if those exact words don't appear in the surrounding text.

`summarize_chunks` iterates over all chunks and applies this logic conditionally. Pure text chunks are stored as-is since their content is already embeddable. Only mixed-content chunks (those with tables or images) go through the LLM. This is an important optimization — calling the vision model for every chunk would be slow and expensive, so we gate it on whether there's actually non-text content present. If the AI call fails for any reason, we fall back gracefully to the raw text so the pipeline never hard-fails on a single bad chunk.

Each output is a LangChain `Document` where `page_content` holds the enhanced (or raw) text for embedding, and the `metadata.original_content` field stores the raw text, table HTML, and image base64 as a JSON string for later use in answer generation.
